# Release Notes

## 0.4.1 — 2026-10-01

Fixes found by installing 0.4.0 from PyPI and npm and following the public documentation as a new user would. The browser package and the Python package are updated together.

### Fixed

- **The password reset forms work in browsers again.** Since 0.3.0 both the request form and the set-new-password form returned 403 in Chrome. The reset pages sent `Referrer-Policy: no-referrer`; under that policy a browser sends `Origin: null` with the page's own form posts, and the CSRF check, which matches the Origin against the request's host, rejects `null` as cross-site. The pages now send `Referrer-Policy: same-origin`: the link carrying the token is still never sent to another site as a Referer, and the page's own posts carry their real Origin. The CSRF check itself is unchanged; do not turn off `web.security.csrf.check_referer` to work around a 403, which reopens login CSRF. The built-in Admin's `/admin/password-reset` and every project using `PasswordResetFlow` were affected. The installed-wheel Admin gate now requests a reset, follows the mailed link, sets a new password and logs in with it, in real Chrome.
- **A rejected CSRF check says what to do.** The 403 page claimed "You do not have permission to access this page."; it now says the page has expired or the request could not be confirmed as coming from this site, and to reload and try again. CSRF failures raise `oldman.web.exceptions.CSRFFailure`, a subclass of `Forbidden`, so handlers of `Forbidden` keep working. Error page templates receive a `description`, set only by an exception that carries `page_description`; other exception messages still never reach the page. JSON error responses are unchanged.
- **The migration commands ask in the CLI's language.** The questions of `db migrate`, `makemigrations`, `downgrade`, `retire` and state recovery, and their fixed answer options, were English whatever language the CLI used. The options keep their English values, so code that answers by value is unaffected, and an answer may be typed in either language.
- **One-off commands keep INFO log lines off the terminal.** `createsuperuser`, `loaddata` and other App commands printed lifecycle lines between their questions and results. The terminal now shows warnings and errors; the command's log file keeps every line. With DEBUG logging (`core.debug`, or `logging.level: DEBUG`) the terminal shows everything. Service lifecycle commands are unchanged.
- **New projects use the Python and Sass versions the framework is tested with.** Every project template writes `.python-version` (3.13) and declares `requires-python = ">=3.12, <3.15"`; `uv sync` used to pick the newest interpreter installed. The dashboard template declares `sass` 1.69.5, the version oldman-web uses, instead of asking you to `pnpm add -D sass`, which installed the newest Sass and fifteen deprecation warnings with it.
- **oldman-web's SCSS uses the Sass module system.** The select and slider styles imported Sass files with `@import`, which Dart Sass deprecates and warns about in every build with a recent Sass. They use `@use` and `@forward` now; the compiled CSS is byte-for-byte the same.
- **The dashboard template's build no longer warns about the ApexCharts chunk.** It is about 580 kB and loaded only on pages with a chart; the warning threshold is 600 kB, so any other large chunk is still reported.
- **The HTTP client logs its initialisation once**, not once in `MultiHttpClient` and again in its backend.
- **A chart's `meta` is the caption shown under it.** The documentation described it as values echoed back, such as the current `range`, while the chart shell shows keys and values to the reader as they are. It now says both should be translated text, and the placeholder `get_result` no longer returns a raw `range` key.
- **`oldman.testing.gate_settings` points `web.domain` at the gate's own server**, so links built outside a request, such as reset mails, reach it.

### Changed

- **`stop` reports in a sentence.** It printed the stopped main process's pid alone and nothing when no service ran; it now prints "Stopped web (main process 1234)." or "web is not running." in the CLI's language. `stop()` still returns the pid for code that calls it.

### Added

- **`oldman --version`** prints the installed version, inside or outside a project, without asking for a language first.

### Documentation

- **The uvloop debug-mode limitation is corrected.** With asyncio debug mode on (`core.debug`), uvloop 0.22.1 and 0.23.0 can raise an error or crash when they finalize an async generator that was not closed. Whether it happens depends on the CPython patch release and on the code: the upstream reproduction crashes on 3.12.14, 3.13.15 and 3.14.2, while the framework's own tests crash on 3.13.15 and 3.14.7, so no patch release is safe for all code and the earlier advice to use 3.13.11 or 3.14.2 is withdrawn. Production runs, without debug mode, are not affected; closing async generators explicitly (`contextlib.aclosing`) avoids it.
- The README mentions that the first command asks for the CLI's language, and the demo setup guides describe `web.domain` and the built-in `DEFAULT` Redis and NATS connections.

### Verification

ruff, pyright and Pyrefly, 2,461 Python tests, the oldman-web (627) and admin (4) frontend test suites, and the boundary, packaging and scaffold matrix checks all pass; the two tests still skipped are the NATS credentials check and the Django interop check. The installed-wheel Admin gate now also requests a password reset, follows the mailed link, sets a new password and logs in with it in real Chrome, and fails against the 0.4.0 reset pages. Both demo apps pass their real-browser acceptance gates, including a new password reset gate in the dashboard demo and the notification gates in Chrome and Firefox.

## 0.4.0 — 2026-09-30

The browser package and the Python package are updated together. This release includes breaking changes, so the minor version is bumped accordingly.

### Breaking Changes

- **`startproject`, `startapp` and `startservice` no longer read answers piped into stdin.** Their questions now come from `oldman.cli.tui`, which does not read stdin that is not a terminal: answers matched to questions by line order go to the wrong question as soon as a question is skipped, added or moved, and nothing reports it. Unattended runs preset each answer instead, for example `OLDMAN_ANSWER_STARTPROJECT_TYPE=web OLDMAN_ANSWER_STARTPROJECT_DATABASE=sqlite oldman startproject site`; the developer CLI reference lists the variables. Without a terminal, a question with no preset answer and no default fails with exit code 2 and names the variable to set. `startapp`'s display name has a default, so an unattended run may leave it out.
- **`createsuperuser` and `changepassword` no longer read passwords piped into stdin** either. Scripts run `createsuperuser --noinput --username … [--email …]` with `OLDMAN_SUPERUSER_PASSWORD`, as before, and give `changepassword` its password in `OLDMAN_ANSWER_CHANGEPASSWORD_PASSWORD`. Without a terminal, a question without an answer is an error that names what to set.
- **`ConsoleMigrationInteraction` no longer takes `input_stream` / `output_stream`.** It asks through `oldman.cli.tui`; migration questions still require stdin and stdout to be terminals and have no preset answers, so `db migrate > out.txt` never waits on a question nobody sees: a decision that needs a person (first use, lost state, a rename or a drop) fails at once, and plain pending migrations are all applied, as before. A choice may now also be answered with the option's text.

- **A `SimpleApplication` service that fails now exits non-zero.** An exception from `prepare()`, `before_start()`, `main()` or a stop hook was logged in one line, without its traceback, and the process exited 0 unless the error came from Taskiq or NATS, so a process manager that restarts on failure never saw it. It is now logged with its traceback, including each sub-exception of an `ExceptionGroup`, and raised, as a Web service does. A stop signal or Ctrl-C still ends the service normally. A Web service's startup error is now logged with its traceback too, not only its repr.

- **Web and `SimpleApplication` services start and stop the way Taskiq services do.** `start` holds a lock on the PID file for the whole run and writes an identity record beside it (`pids/<service>.identity.json`, which replaces the Taskiq services' `.taskiq.json`); the service owns a process group. `stop` verifies that record, sends SIGTERM to the main process and returns only once the whole group has exited, Sanic workers included, killing the group after `process.stop_timeout` seconds (new setting, default 60; Taskiq services keep `taskiq.stop_timeout`); processes the service starts while it stops are stopped with it. It prints the main process's pid. `restart` stops that way, then starts. A PID file written by an earlier version has no identity record, so `stop` refuses to signal its pid: stop such a service with the version that started it, or remove the file if nothing runs. The identity record is replaced in one step; one that cannot be read (edited by hand, damaged on disk) is removed by `stop` as a leftover while no run holds the lock, and while the service runs `stop` refuses and names its main process. Calling `stop()` from inside the running service is refused. Called on `current()`, the instance a running service, worker or App command uses, `stop()` (refused or not) and a refused `start()` leave that process's logging open: the command line closes the logging of the instance it builds for a command when the command ends, and a service's own `run()` closes it when the service ends. When a run's main process was killed while processes it started live on, `start` and `stop` both refuse and list them with the `kill -TERM -<group>` that ends them; when the main process still runs and only its PID file was removed, `start` says the service is running and `stop` still finds it. Started by a script, the service takes the terminal's foreground only when its stdin is the terminal, so one the script puts in the background with `&` leaves Ctrl-C to the script; a terminal that has hung up no longer makes it exit with an error. A service that is its container's PID 1 is stopped from outside, by the container runtime: `stop` and `restart` run inside that container refuse and signal nothing, since signalling process group 1 reaches every process there. An App command's lock file is now `<service>.<command>.pid`: with `_` between the two, service `a_b` and command `b` of service `a` shared `a_b.pid` and kept each other from running. A child the service forks does not keep it locked; a child that leaves the process group itself (`setsid`, `setpgid`) is not waited for or killed by `stop`.

### Added

- **`oldman.cli.tui`, terminal interaction for commands and ops tools.** Output (`echo`, `info`, `success`, `warning`, `error`, `table`, `rule`), waiting indicators (`spinner`, `progress`, drawn from their own thread so the block can await), questions (`ask`, `confirm`, `choose`, `choose_many`), forms (`Field`, `ask_form`, with remembered answers, checked again before they are offered as defaults) and menus (`Menu`, `Item`, `run_menu`, with submenus built on demand; a failing entry shows one line, and its traceback is logged at DEBUG for debug mode). Everything is plain text, never Rich markup; `echo` writes its line unchanged, tabs and control characters included; a non-UTF-8 terminal gets ASCII symbols. Waiting indicators can be nested. The dependency is now `rich>=14.1`. In a `raw_stdout` command everything but `echo` goes to stderr. A question is asked only when stdin and the stream it is written to are both terminals, so a program that runs a command and captures its output never leaves it waiting on a question; otherwise the question takes its preset answer or default, or fails naming the variable to set. Ctrl-C and the end of input raise `tui.Cancelled`, which the CLI reports as "Aborted." with exit code 1; Ctrl-C interrupts a question at once inside `asyncio.run` too. `simulate_input` answers questions in tests.
- **Preset answers.** A question given a `key` is answered by the environment variable `OLDMAN_ANSWER_<KEY>` without being asked, in a terminal or not, like Debian's preseeding. The value is checked as a typed answer would be, and one that does not fit is an error naming the variable. A preset choice is matched by the option's value, then its text, then its number, so a preset `1` picks the option whose value is `1`; a typed choice by the text shown, then the number, then the value, so a typed `1` is the first entry even when a hidden value is `1`.
- **`oldman.ops`, building blocks for maintenance tools.** `edit_marked_block` and `set_directive` / `read_directive` edit configuration files and can run again and again; `os_release` reads the system's identification; `oldman.ops.systemd` checks, restarts and reloads units, with the `systemctl` command (and whether it needs `sudo`) chosen by the caller; systemctl runs in the foreground on the tool's terminal, so `sudo` can ask for a password. A failure raises `subprocess.CalledProcessError` with systemctl's output, and a missing `systemctl` raises `FileNotFoundError`. File edits take an explicit `follow_symlinks`, as `atomic_write` does.
- **`oldman.processes.run_foreground`, for commands a person may answer.** It runs `subprocess.run` in a worker thread: the child stays on the caller's terminal, so `sudo` can ask for a password and Ctrl-C reaches it, while the event loop keeps running; results and errors are the standard library's. `run_subprocess_exec` remains the choice for children no person talks to, in a web service, a taskiq worker or a job that needs its whole process group cleaned up; its child has no controlling terminal, so `sudo` cannot ask for a password and Ctrl-C does not reach it. `oldman.ops.systemd` and remote scripts run through `run_foreground`.
- **`oldman.cli.remote`, remote files in an ops tool's menu.** `RemoteFiles(base, cache_dir=...)` takes an `http(s)://` address (a GitHub raw URL with a tag in it, a file server; `user:pass@` is allowed and never shown in errors or logs) or a local directory while developing. `menu(path)`, `action(path)` and `script(path, *args, interpreter=...)` give what `tui.Item(load=...)` and `tui.Item(action=...)` take: a remote Python file defines `async def menu()` or `async def run()` and runs inside the tool's command, with the database and settings ready; a script runs in the foreground on the tool's terminal. Downloaded files are cached per base address, work offline and change only on `refresh()`, which skips and reports the files it cannot download; `fetch(path)` returns any file's local copy.

### Fixed

- **A Web or background service's PID file no longer points at the wrong process.** Whether a service ran was judged by `/proc/<pid>`, so a PID file left behind after a crash or a reboot stopped the next `start` once its number belonged to another process, and `stop` sent SIGTERM to that unrelated process. The file was removed only when the service's parent was PID 1: started from a shell it stayed behind, and a `stop` run by systemd (parent PID 1) deleted the running service's file as it exited. `restart` waited without limit. The lock and identity record above replace all of this.
- **The Typer requirement matches what the CLI uses: `typer>=0.26.0,<0.28`.** The CLI builds on Typer's bundled Click, `typer._click`, which Typer ships from 0.26.0; with the old floor of 0.16.1 an install could pick a Typer on which `oldman --help` already failed to import. The bundled Click is private to Typer, so the range stops before the next minor release until that one is checked.
- **A `SimpleApplication` service no longer ignores a stop signal that arrives as its event loop starts.** It installed its SIGTERM and SIGINT handlers before the loop ran, and uvloop drops a signal that arrives in between, so the service ran on and `stop` had to kill it at the deadline. The handlers are now installed once the loop runs; a signal before that ends the process, as during `init()` and `prepare()`.
- **A table refresh that fails no longer leaves an unhandled Promise rejection.** A reload event, typing in the search box, paging, changing the page size, sorting and the empty state's Reset filters button refresh the table with nothing awaiting the result. A failure (a 401 once the session has expired, a 500, a lost connection) was shown on the table and emitted as `om:table:error`, then raised again, reaching the page's unhandled-rejection handlers as a page error. `refresh()` and `reload()` called directly still reject.
- **Waiting for a process group to exit no longer keeps a CPU core busy.** `stop` and the cleanup of a managed subprocess scanned all of `/proc` at every poll, about 45 ms each on a host with 600 processes: a `stop` waiting 3 seconds for a service that ignored SIGTERM used 1.1 seconds of CPU. They now ask the kernel whether the group is empty and look at the members already known, and scan only when a member not seen yet may be left; the same wait uses 0.05 seconds.
- **A Web service stopped while its workers start no longer hangs.** Sanic 25.12.1's worker manager waits for the workers' startup acknowledgements in a loop that does not recognise the shutdown signal's message: it put the message back and waited again, so a SIGTERM in that window left the primary process spinning a CPU forever after its workers had exited. The framework replaces `WorkerManager.wait_for_ack` with a copy that hands the message on to the manager's shutdown, until a Sanic release fixes it.
- **New projects ignore `logs/` and `pids/`.** Every project template with a service lists in its `.gitignore` the two directories the default `logging.dir` and `process.pid_dir` point at; a new project's first command used to leave an untracked `logs/`.
- **`settings sync` no longer adds every field description again.** A description written above a key was read back attached to the value before it, so each sync added the roughly thirty descriptions once more. Sync now removes comment lines that repeat a field description and puts each description back above its key once, so the file no longer grows with every run; duplicates left by earlier versions merge into one on the next sync, and other comments are kept. Descriptions of App settings are indented to their keys under `app_settings`.
- **The first migration file's `Revises:` line has no trailing space**, which ruff reported as W291 in projects that enable the W rules.
- **Four CLI messages are translated**: the error for a missing settings file and three messages of the frontend language pack commands were missing from the CLI's message template and catalogs, so they showed in English in the Chinese interfaces.

### Verification

ruff, pyright and Pyrefly, 2,452 Python tests, the oldman-web (627) and admin (4) frontend test suites, and the boundary, packaging, and scaffold matrix checks all pass. The Redis, NATS and Taskiq checks run against real servers and fail rather than skip when one is missing; the two tests still skipped are the NATS credentials check and the Django interop check. The service start and stop protocol was also checked by mutation testing, so that breaking any of its checks fails a test, and its timing-sensitive tests ran fifty times in a row without a failure. Both demo apps pass their real-browser acceptance gates, including the notification gates in Chrome and Firefox.

## 0.3.0 — 2026-09-28

The browser package and the Python package are updated together. This release includes breaking changes, so the minor version is bumped accordingly.

### Breaking Changes

- **Staff reach Admin models only through their roles.** Being staff now only lets an account sign in to the Admin. Registering a model declares four permissions for it, `admin.<app_label>.<model>.view`, `.add`, `.change` and `.delete`, named after the model class in lower case under the App that defines it, as Django does (`admin.examples.exampleproject.view`; `ModelAdmin.permission(action)` returns one), and a staff user needs a role that holds the one an action checks; superusers hold them all. A model with `require_superuser` declares none, since no role could open it. A service without `oldman.apps.roles` admits only superusers to its models. Table names play no part, so a legacy table such as `LegacyOrders` registers like any other; two models that would reach the same name are refused rather than made to share it. A model registered before the service loaded its models is refused when the Admin installs its routes: its permissions were declared without the App's label and would be checked with it. Without view a model leaves the menu and its list answers 403; without add the New button is gone; without delete the edit page shows no Delete button. Row actions in the table stay visible and answer 403 when used. `ModelAdmin.has_view_permission`, `has_add_permission`, `has_change_permission` and `has_delete_permission` are now coroutines; all but add also take the object once the handler has loaded it (`obj=None` before that), so an override can add a condition on the object. `AdminSite.menu_items` and `menu_groups` are coroutines that take the request. User management is the exception: it checks the auth App's own permissions, `auth.users.view`, `.add`, `.change` and `.delete` (`oldman.auth.user_permissions`, declared by services that install `oldman.auth`), the same ones a project's own user pages check. Only superusers still manage staff and superuser accounts, whatever a role grants.
- **Every Redis key and channel now lives under `core.namespace`.** It defaults to `core.app_name`, which must then be usable as one: not empty, no `:` or whitespace. Otherwise the settings fail to load and ask for `core.namespace`. Services that share sessions, tokens or cache — a public site and its dashboard, say — set the same namespace; a service that must stay apart sets its own. Services that leave it unset share only when their `app_name` is the same: with different names, a password changed on one does not end the other's sessions or tokens, and the other's caches are not invalidated. The settings that used to name some of these keys are removed: `web.session.prefix`, `web.session.user_prefix`, `web.sse.channel_prefix` and `cache.namespace`. Sessions, SSE (`<namespace>:events:v1`), the cache, the model cache, dynamic settings, rate limits, fingerprint security, tokens, locks, the image cache index and the stream proxy all build their keys through `oldman.providers.redis.redis_key()`. Taskiq results and schedules keep `taskiq.namespace`, which is what their producers and consumers share, and the Django-compatible cache keeps Django's key format.
- **Public ids use an alphabet of each deployment's own.** `oldman.utils.hash_ids` encoded ids with an alphabet written into the source (`SQIDS_ALPHABET`, now removed). It now reads `core.id_alphabet`, which `settings init/sync/write` generate at random for a Web service while it is empty, and `encode_id` / `decode_id` raise until it is set. `decode_id` also returns None now for a string that decodes to more than one number, which `encode_id` never produces.
- **`get_app()` is removed; register routes through `router`.** `oldman.web.get_app` handed views the whole Sanic instance, yet every call in the framework, the scaffolds, the documentation and both demos only registered routes. `router` exposes route registration and nothing else.
- **`oldman.utils.headers` is removed**, along with the `fake-useragent` dependency it alone required. It generated fake browser User-Agent strings, which is scraping tooling rather than part of a web framework. Outbound requests take their User-Agent from `http_client.user_agent`.
- **`DataclassModelMixin` decodes by the field types.** `from_dict`, `from_json_bytes`, `from_json_str` and `from_msgpack` passed the decoded mapping to the constructor as it was: dates, enums and nested dataclasses stayed strings and dicts, a value of the wrong type went in unchecked, and an unknown key raised `TypeError`. They now decode through msgspec like `MsgspecModel`: each field comes back as its declared type, a value that does not fit raises `msgspec.ValidationError`, and unknown keys are ignored.
- **The rest of `oldman.utils` was cleaned up.**
  - Removed modules: `loop_utls` (`AsyncToSync`, `cancellable_sleep`, `ensure_async_context`, `use_uvloop`), `thread` (`ThreadPool`, `AsyncTask`, `handle_timeout`) and `console`.
  - Removed: `Singleton`, `SingletonCallable`, `SingletonContainer`, `singleton_container`, `SingletonDict`, `SingletonList`; `collections_utils.SerializableMixin`, `SerializableProtocol`, `DataclassProtocol`, `NO_DEFAULT`; `crypto.generate_token`; `date.convert_cst_to_utc`, `convert_cst_to_utc_text`; `hash_ids.SQIDS_ALPHABET`; `http.my_url_join`; `strings_utils.get_url_from_params`, `get_url_from_query_string`.
  - Renamed or moved: `safe_cancellable_sleep` is in `asyncio_utils`; `singleton_adv` is `singleton`; `filter_bytes` is `clean_text`; `generate_unique_slugs` is `unique_slugs` and returns a list in the order of the names; `get_nested`, `is_iterable_like`, `variadic`, `try_call`, `try_get` and `filter_dict` are static methods of `CollectionUtils`, where `get_nested` takes the keys as separate arguments and also indexes lists, `variadic`'s `allowed_types` is `scalar_types` and `filter_dict`'s `cndn` is `predicate`.
  - New: `asyncio_utils.run_sync`, `new_event_loop` and `interruptible_sleep`; `http.append_query`; `date.convert_to_utc_text`.
  - Same names, different behaviour:

    | Function | Change |
    | --- | --- |
    | `files.check_file_mtime` | Synchronous. |
    | `files.load_json_file` | A file that is not valid JSON raises `orjson.JSONDecodeError`; a missing file still returns None. |
    | `files.save_json_file` | Raises on failure; replaces the file in one step and creates missing directories. |
    | `strings_utils.json_dumps` | `json_dumps(data, *, option=None)`, passed on to `orjson.dumps`. |
    | `http.update_url_query` | `update_url_query(url, params=None, /, **kwargs)`. Parameters it does not change keep their spelling and order, those without a value included; a value of `[]` removes the key. |
    | `http.get_server_timestamp_from_header` | Returns None when there is no usable `Date` header; `Last-Modified` is read only with `use_last_modified=True`; RFC 850 and asctime dates parse too. |
    | `strings_utils.get_full_ext_from_filename` | A compound extension only after `.tar`: `backup.tar.gz` is `.tar.gz`, `report.2024.gz` is `.gz`. |
    | `strings_utils.get_ext_from_filename` | Only `?` and `#` end a plain file name, no longer `$`. |
    | `date.ElapsedTimer.stop()` | Measures with `time.perf_counter()` and rounds to three digits; `stop(unit, ndigits)` chooses the unit and precision. |
    | `crypto.constant_time_equals` | Compares text by its UTF-8 bytes, so non-ASCII text and `str` against `bytes` compare instead of raising `TypeError`. |

- **`revoke_user_sessions` is now `revoke_user_logins`**, because it ends more than sessions: every access token the user was issued is revoked with them.
- **`app.ctx` keys lose their `oldman_` prefix.** Inside the framework's own namespaces the prefix carried no information. `app.ctx.oldman_app_registry` is now `app.ctx.app_registry`; the Admin keys `oldman_admin_extension_bundle_name`, `oldman_admin_notification_routes` and `oldman_admin_user_events_url` are now `admin_extension_bundle_name`, `admin_notification_routes` and `admin_user_events_url`. Names in namespaces shared with others keep the prefix: table names, the flash cookie, SQLAlchemy and Alembic `info` keys, environment variables.
- **Framework classes lose their `Oldman` prefix.**
  - `OldmanHTTPMethodView` → `HTTPMethodView`. `oldman.web` no longer re-exports Sanic's class of that name beside it; the framework's subclass behaves exactly like Sanic's while `require_authenticated` and `require_staff` are off, which is their default.
  - `OldmanForm` / `OldmanModelForm` → `Form` / `ModelForm` in `oldman.web.components.forms`. WTForms' own `Form` is a different class.
  - `OldmanErrorHandler` → `ErrorPageHandler`, which says what it does: render the project-overridable error pages.
  - `OldmanBaseModel` → `ConfigModel`, matching the `XxxConfig` settings sections built on it.

- **`web.debug` is now `core.debug`.** Beyond the Web server it sets the SQL echo default (`database.echo: null`) and the stream proxy's error tracebacks, which every service uses.
- **`logging.level` defaults to null, which follows `core.debug`:** DEBUG when it is on, INFO otherwise. A configured level still wins. `LoggingConfig.resolved_level(debug=...)` gives the level to install.
- **`oldman.conf.constants.DEBUG` and `TEMPLATE_DEBUG` are removed.** Nothing read them; the debug switch is `core.debug` in settings.
- **`web.security.token_expire_time` is removed.** Nothing read it. Access token lifetime is `web.auth.jwt.access_token_ttl`.
- **`oldman.db.services` is removed.** It only re-exported `BaseModelService`, which lives in `oldman.db.sqlalchemy.services`.
- **`SettingsManager` no longer takes `deprecated_keys`**, and the table of old settings keys it named replacements from is gone.
- **Unused token schemas are removed from `oldman.db.schemas`:** `Token`, `TokenData` and the `TokenBlacklist*` models. Nothing used them, and a blacklist keyed on the token string can be bypassed by re-spelling the same token; access tokens are revoked by their `jti` instead.
- **`api_authorized` and `api_key_authorized` are removed.** Shared secrets are named under `web.auth.api_keys` and checked with `authenticated_by("api_key")`; loopback callers are admitted through `web.auth.ip_allowlist`. A missing or wrong key is 401.
- **The model cache was rebuilt, and its second row cache is gone.** `cached_model_simply`, `AsyncModelCache` and `CacheConfig` are removed: they kept rows under keys `cached_model` never invalidated, and their background write after a commit could put an older row back over a newer one. `AsyncQueryCache.invalidate(*instances)` is removed too: writes through the ORM invalidate on commit, `M.invalidate_cache_on_commit(session)` covers bulk statements and raw SQL inside a transaction, and `await M.invalidate_cache()` covers changes made outside the application.
- **Cached reads return detached snapshots.** With the cache on — hit, miss or bypass alike — `cached_get`, `cached_get_many` and `cached_filter` return rows with every column loaded, an identity, and no session; a relationship that was not loaded raises `DetachedInstanceError` instead of reading as empty. With `use_cache=False` they are plain queries as before. The switch has that one name on all four methods — `cached_filter` and `execute_query` called it `cache` — and is keyword-only, so `cached_get(session, 1)` no longer takes the 1 as the switch. `save()` on a snapshot writes it back, but `update()` raises `InvalidRequestError`, since the snapshot is not in that session.
- **The model cache refuses what it cannot serve correctly.** `@cached_model` raises `TypeError` at declaration for a model without a single primary key column, with mapper inheritance, with a column type it cannot round-trip (a project's own `TypeDecorator`, `ARRAY`), with a deferred column (never loaded with the row, so no read could be cached), or with a foreign key the database cascades on (`ondelete` `CASCADE` / `SET NULL` / `SET DEFAULT`, `onupdate="CASCADE"`) whose target is missing from `invalidate_on` — and so is every table further up a chain of such keys, since deleting a team takes its projects and their tasks with them; a table on the chain that is not defined yet is refused as well. The cached methods raise `ValueError` for a statement that reads another table, selects columns rather than whole rows, locks (`with_for_update`), carries loader options or has a bound parameter computed by a callable (`bindparam(..., callable_=...)`, whose value SQLAlchemy's statement cache key does not carry); for a session connected to a different database than the cache's `db_manager`; and for an in-memory SQLite database.
- **`db_manager.transaction()` no longer takes `nested`.** `transaction(nested=True)` opened a savepoint on a new session, so SQLAlchemy began an outer transaction around it that nothing committed: leaving the block released the savepoint, and closing the session rolled every write back, without an error, on PostgreSQL and MySQL. SQLite's default savepoint handling commits on release, which hid it. A savepoint belongs on the session that holds the transaction: `async with session.begin_nested():`.
- **CSRF tokens are bound to the session, or to a cookie for anonymous visitors.** A token was meant to be bound to the session but was bound to the user id, which `SessionData` holds instead of a session id: another session of the same user, or a new login after signing out, accepted it. Every anonymous token bound to the same value, and an anonymous request skipped the comparison, so any visitor's token passed for any other. A signed-in request now binds the session id the Session middleware captured; an anonymous visitor gets a random id in a cookie, as Django does, named by the new `web.security.csrf.cookie_name` (default `csrf_id`; not `csrftoken`, which the frontend reads as a token). The Session middleware writes it with the session cookie's Domain, Secure and SameSite, HttpOnly, Path `/`, for a year, on the first response that generated a token; nothing is stored on the server and no anonymous session is created. A service without the Session middleware keeps anonymous tokens unbound, relying on the Origin check. `cache_response` no longer stores a response whose request generated a token. A form opened before signing in needs a reload after it. A signed-in session's token also records the browser's CSRF cookie, which is issued to signed-in pages too and outlives the session, as in Django: a form left open until its session ended (expired, signed out elsewhere, or ended by an administrator) passes as the same browser's, and the now anonymous request goes on to the view's sign-in check, which sends the user to the login page instead of showing a CSRF error. A signed-in request is still compared with its session only, so signing in again in the same browser still invalidates the old tokens. `Session.send_cookie()` and `Session.opened_session_id()` are the Session side of this.

### Added

- **Typed runtime configuration: `YamlStore`, `RedisStore` and `RedisSet`** in `oldman.conf.containers`. A `MsgspecModel` subclass declares the fields, their types and their defaults; every field needs a default, because a missing file or key reads as the defaults. `get()` returns the decoded value. `save(value)` validates it against the schema before writing, since msgspec checks no types on construction or assignment. `update(**changes)` reads the value, changes top-level fields and hands it to `save()`, so a subclass that overrides `save` covers both, and returns the validated value it saved; updates in one process run one after another, so concurrent changes to different fields are all kept, and `YamlStore.update` rereads a file another process changed first, whatever `check_interval` says. `YamlStore` keeps the decoded value in memory and checks the file every `check_interval` seconds. It calls `on_file_changed(old, new)` only when the file was changed from outside, deletion included, never for its own saves; an outside edit that does not match the schema, or is not UTF-8, is logged and the last valid value kept. Saving does not keep YAML comments. `RedisStore` stores the whole value as msgpack under `<namespace>:store:<name>` and reads Redis on every `get()`; a stored value that no longer matches the schema raises rather than reading as the defaults. `RedisSet` is a native Redis set of `str` or `int` members under the same prefix: `add`, `remove`, `contains`, `members` and `random` each run as one set command, so an allowlist can be checked on the request path without loading it.
- **IP allowlist.** List `ip_allowlist` last in `web.auth.authenticators` and name networks under `web.auth.ip_allowlist` (entry name to addresses or CIDR blocks). The entry name becomes `request.ctx.auth.caller`; `request.ctx.user` stays anonymous. A request is recognized only when its socket peer (`request.ip`) and its client address (`request.client_ip`, from the proxy headers) both fall in the same entry, because Sanic believes `web.real_ip_header` from any client: behind a proxy, the entry lists the proxy's address beside the clients'. IPv4 callers seen by a dual-stack listener as `::ffff:a.b.c.d` are matched as IPv4. A block with host bits set is refused rather than widened, and listing `ip_allowlist` anywhere but last is refused at startup, since it would hide the session of a signed-in user on an allowed network. These requests stay CSRF-checked.
- **HTTP Basic.** List `http_basic` in `web.auth.authenticators` and set `web.auth.http_basic.accounts` (username to password) and `realm`. The account name becomes `request.ctx.auth.caller`; `request.ctx.user` stays anonymous. Username and password are compared in constant time for every account. A browser remembers Basic credentials and sends them by itself, so these requests stay CSRF-checked. `authenticated_by("http_basic")` answers a refused request with 401 and `WWW-Authenticate: Basic realm="..."`, which makes a browser show its sign-in prompt; listing `session` as well sends browsers to the login page instead. `basic_credentials(request)` in `oldman.web.request` reads the header.
- **API keys and `authenticated_by`.** List `api_key` in `web.auth.authenticators` and name keys under `web.auth.api_keys`: a caller sends one in the `X-API-Key` header, and a key that opts in is also read from its `query_param` or from `Authorization: Bearer`. Keys are compared in constant time. The caller is not a user: `request.ctx.user` stays anonymous and `request.ctx.auth.caller` is the key's name. `authenticated_by(*methods, callers=None)` in `oldman.web.auth` admits a request only when one of the listed methods recognized it, and with `callers` only those keys; users signed in by a listed method are not restricted by `callers`. Nothing recognized is 401, anything else 403, as JSON unless `session` is listed. Requests authenticated by a key are not CSRF-checked unless a signed-in session came along.
- **Roles on the user form.** Where the roles App is installed and at least one role exists, the shared user create and edit forms carry the roles as checkboxes, and the edit page ticks the ones the user holds. `await form.save_roles(session, user)` writes them in the same transaction once the user row has an id and reports whether they changed; the Admin then ends that user's logins after the commit, as it does for changed access flags. The form needs a session to list the roles.
- **Role management in the Admin.** When a service installs `oldman.apps.roles`, `install_admin` registers the role model with `RoleModelAdmin`, unless the project registered it already. Roles are edited with `oldman.apps.roles.forms.RoleForm`: a unique name, a description, and every declared permission as a checkbox grouped by the App that declares it. A save changes only the permissions this service declares; names it does not know, such as another service's on a shared role table, are kept as they were. Once a save commits, the role's cache key is rewritten; if Redis refuses, the response is 503 in the framework's envelope (`ApiErrorCode.SERVICE_UNAVAILABLE`, 1503) so the Admin shows its translated message, the role stays saved, and saving it again repairs the key. Any `after_save` that raises `ServiceUnavailable` is answered the same way on the Admin's form requests. A delete drops the key inside its transaction before the row goes, and again after the commit; if Redis refuses, nothing is deleted and the response is 503. `oldman.web.auth.roles_installed(app)` tells whether a service has roles.
- `ModelAdmin.after_save(request, instance, *, created)` and `after_delete(request, instance)` run once the Admin's transaction has committed — `after_save` also after the user manager enables, disables or sets the password of a user, which save that row too; they do nothing by default. `AdminSite.is_registered(model)`.
- **`CheckboxGroupField`** in `oldman.web.components.forms`: several values from fixed choices, rendered as checkboxes rather than a list box. Grouped choices (a dict of group label to choices) get a heading per group. `DataRequired()` means at least one box, never every box.
- **Permission declarations.** An App declares the permissions its code checks in its `permissions` module, as `PermissionSet` classes (`class ReportPermissions(PermissionSet, namespace="reports"): export = Permission(_("Export reports"))`) or with `declare_permission()`. Names are `<namespace>.<codename>` and are not tied to models. A name is declared once, and at startup every namespace must be an installed App's label. Every service imports them right after its models, at `bootstrap_service()` — the Web one therefore before its views, and a command or worker that creates roles finds them declared; `declared_permissions()` lists them. Declaring grants nothing to anyone. Every service imports each App's `permissions` module, so an App whose existing module of that name does something else sets `permissions_module` in its `AppConfig` to another name; a module that does not exist is skipped.
- **Roles.** The installable `oldman.apps.roles` App stores roles — named sets of permission names — and which users hold them (`oldman_role`, `oldman_user_role`). `oldman.apps.roles.store` keeps each role's permissions in Redis under `<namespace>:role:<id>` with the database as the source of truth: saving writes the key after the commit, deleting removes it, and a missing key is read from the database and written back only if it is still missing. Role ids are never handed out again, except on MySQL 5.7 and earlier, which restart the auto-increment counter from the highest id after a server restart. `replace_user_roles()` replaces a user's roles inside the caller's transaction and reports whether they changed.
- **Permission checks.** `has_perm(request, permission)` and `require_perm(request, permission)` in `oldman.web.auth` answer whether the request's user holds a declared permission: a superuser holds all of them, anyone else what the roles in their login grant. Sessions carry the user's role ids (`SessionData.role_ids`, `request.ctx.user.role_ids`), read at login when the roles App is installed, and access tokens carry them in a required `roles` claim — tokens issued without it are refused. The roles' permissions are read once per request, roles missing from the cache through `db_manager=` when given (the Admin passes its own) and the process's database otherwise; an unreachable store answers 503. `permissions_not_held(request, names)` lists the names the user does not hold (none for a superuser), for handing permissions on: the shared user form refuses to give a new role whose permissions the operator does not all hold, and `RoleForm` to add a permission the operator does not hold — removing, or keeping what was there, is not restricted. Otherwise whoever may edit users or roles could grant more than they have.
- `core.namespace`, and `redis_key(*parts)` / `redis_namespace()` in `oldman.providers.redis` for a project's own keys.
- `oldman.testing.use_owned_redis(payload, redis_url)` points every Redis alias of one settings payload at a gate's own Redis, one database each, and leaves the rest as it was; the built-in DEFAULT, CACHE and SESSION aliases are added when the payload leaves them out, since they would otherwise use their `localhost:6379` defaults. It is for tests that run real commands in a temporary project without the full gate settings. `gate_settings` uses it.
- `oldman.web` now exports `BadRequest`, `Unauthorized` and `TooManyRequests`, next to `NotFound` and `Forbidden`. Applications no longer need to import HTTP exceptions from the underlying server package.
- **`request.ctx.user` and `request.ctx.auth` on every request**, whatever authenticated it. A pipeline installed right behind the Session middleware tries the methods listed in `web.auth.authenticators` in order; the first to recognize a credential decides. `request.ctx.user` is a snapshot of the signed-in user (`id`, `username`, `display_name`, `is_staff`, `is_superuser`) or the anonymous user; `request.ctx.auth` says how the request authenticated. Unset, the list is `[session]` when sessions are on. A project adds its own method by import path. `login_user()` and `logout_user()` update both for the rest of the request.
- **Bearer access tokens.** List `jwt` in `web.auth.authenticators` and set `web.auth.jwt.secret` (its own key, at least 32 characters, shared by the services that accept each other's tokens). `issue_access_token(user)` signs a JWT (HS256) carrying the user snapshot plus `iat`, `exp`, `jti`, and `iss` / `aud` when configured; lifetime `web.auth.jwt.access_token_ttl`, 900 seconds by default. Only `Authorization: Bearer` is read. A missing or invalid token leaves the request anonymous, so the permission layer answers 401 — as JSON for a request that presented a bearer token. Token requests are not CSRF-checked unless a signed-in session came along.
- **Refresh tokens.** `issue_refresh_token(user_id)` starts a family per sign-in; `rotate_refresh_token(token)` replaces a token with the next one of its family, which lives `web.auth.jwt.refresh_token_ttl` seconds (7 days by default) from then, so a client that keeps refreshing stays signed in. Redis stores only a SHA-256 of each token. A token that was already replaced and comes back ends its whole family, as does a race between two requests presenting the same one. `revoke_refresh_token(token)` ends a family. `refresh_token_user(token)` tells whose a token is without using it up, so a refresh can check the user first: the token routes do, and a refresh that fails on the way leaves the client's token valid. They also refuse a disabled account a login backend returns, with 401 like any refused one.
- **Token routes.** `TokenFlow(accept_user=...).register_routes(obtain_path=..., refresh_path=..., revoke_path=...)` in `oldman.web.auth` installs the three POST routes a client that is not a browser signs in with: obtain an access token and a refresh token with the credentials the login page takes, refresh the pair, and sign out, which also ends the access token presented with it. `accept_user` decides who may hold tokens and has no default; it is asked again, against the database, at every refresh. A body with a field missing, not text, or holding text UTF-8 cannot carry (a lone surrogate) gets 400. Failed sign-ins count against the login page's limits (429 with `Retry-After`), and a refused account gets the same 401 as a wrong password. Answers use the framework's JSON envelope with `Cache-Control: no-store`, with refusals in the request's language, set no cookie and need no CSRF token.
- `ApiErrorCode.TOO_MANY_REQUESTS` (1429), and `oldman.web.request.request_sends_json(request)`, which tells from the Content-Type whether a request body is JSON.
- **Token revocation.** Changing a password through the framework now also revokes every access token and refresh token the user was issued, by writing a per-user cutoff to the security Redis; an access token issued at or before it, or a refresh token from a sign-in at or before it, is refused. The cutoff lives as long as the longer-lived token. `revoke_access_token(claims)` refuses one access token by its `jti` until it would have expired. `end_user_logins(user_id)` does the same as the request path where there is no request, such as the command line. A service without `web.auth.jwt.secret`, such as an Admin that signs no tokens, writes the cutoff too, so disabling an account or changing its password there ends the tokens another service issued. Services that share users share the jwt settings (the lifetimes decide how long the cutoff is kept), the security Redis and `core.namespace`. When the revocation store is unreachable, token requests get 503 rather than being let through.
- `authenticated_session(request)` in `oldman.web.auth` returns the signed-in browser session or raises 401, for pages about "this session" that a caller authenticated some other way must not reach.
- **Login backends.** `authenticate_credentials(request, **credentials)` in `oldman.web.auth` asks the backends listed in `web.auth.login_backends` in turn; the first to accept the credential returns the User to sign in. The built-in `users` backend is the existing `authenticate_user`; a project adds its own — a device token, say — by import path, with `name` and `async authenticate(request, **credentials)`. The Admin login goes through it.
- `oldman.utils.module_loading.import_string()` and `build_configured()` load and build the objects settings name by dotted path.
- **`current()` on every service class** returns the service instance the current process runs, for code outside the service class — views, background jobs, App commands. It is to a service what the server's `get_app()` was to the application: the whole object, and the real one, so an IDE completes what a subclass defines. Project code asks its own class (`WebService.current()`); reusable Apps ask `BaseApplication.current()` or `WebApplication.current()`. It returns `None` where no such service was constructed — a shell, a plain `bootstrap_service()` script, a Taskiq worker process — so importing code that uses it never fails there. Call it inside functions: a module-level result is fixed at import time. Every service now has `runtime_app`; it is `None` for services that run no Web server and before a Web service creates its application.
- **Model cache partitions and dependencies.** `@cached_model(partition_by=(...))` names integer, boolean, UUID or enum columns, typically a foreign key: a cached query whose WHERE fixes each of them with `==` or `IS NULL` — for a boolean also `flag == True`, `flag.is_(False)`, a bare `flag` or `~flag` — is invalidated only by writes to rows in that partition, before or after the write, while any other query is invalidated by every write to the model. String, date, decimal and float columns are refused, because the database compares them differently from Python. `invalidate_on=(Model, ...)` invalidates the whole cached model when one of those models is updated or deleted through the ORM. A cascade back into the model's own table — a tree's parent key — needs no entry: each update or delete of the model then invalidates all of it. `cached_filter(expire_seconds=...)` and `execute_query(expire_seconds=...)` override the query TTL per call. `Model.get_cache_manager().stats` returns a `CacheStats` snapshot of how the model's cached reads were served in this process — `hits`, `misses`, `bypassed` (the caller's own uncommitted changes, or this process's invalidation still running) and `fallbacks` (Redis failed, or no cache connection in time) — counted per entry, so a hit rate can be checked before deciding a model is worth caching.
- **`database.cache_pool_size` and `database.cache_pool_timeout`** (5 connections, 1.0 second by default). The model cache fills entries through its own small pool on the same database, opened on the first miss and closed with the manager, so a request that already holds a connection never waits for a second one from the main pool. A fill that gets no connection within the timeout reads through the caller's session and stores nothing. Each process may hold up to `cache_pool_size` extra database connections. `DatabaseManager(cache_pool_size=..., cache_pool_timeout=...)` overrides the settings for a manager built by hand.

### Changed

- **Settings files and JSON files are replaced in one step.** `settings init/sync/write`, `save_json_file`, `DataclassModelMixin.to_json_file` and `YamlStore` write a temporary file next to the target and move it over, so an interruption leaves the old file or the new one, never half of one. A symbolic link at the target is followed and kept, as writing through it used to be: services that share one settings file by linking to it stay together. The replaced file then belongs to the user who wrote it. `oldman.utils.files.atomic_write(path, data, *, follow_symlinks)` is the one implementation; callers say whether a link is followed.
- **Settings keys the schema does not declare are reported at every level.** Sections below the top ignore keys they do not know, so a removed or misspelt key used to vanish without a word. Startup and `settings check` now list each one as advice (`unknown settings key 'web.sesion'`). An unknown top-level key is still an error. Connection aliases under `redis` are the project's own names and are not listed; App settings refuse unknown keys as before.
- `PasswordResetFlow.register_routes()` no longer needs an application instance. Omit it and the six views register through `router`; passing one explicitly still works.
- **Importing a views module no longer fails when no Web server exists yet.** `router` used to look the server up the moment a route was registered, so a shell, a `bootstrap_service()` script or an App command that imported views failed with "No Sanic apps have been registered". Registrations made before the Web service creates its application are now recorded and applied when it does, ahead of the views it loads; in processes that run no Web service they simply never take effect. Errors such as a duplicate route name are therefore reported when the application is created, still during startup. `router` now finds the server through the running service instead of the server's global registry.
- **Taskiq needs Redis 6.2 or newer.** taskiq-redis reads task results and schedules with `GETDEL`, which older servers do not have.
- **Every entry point stops in one order: the service's own stop hook, then the framework's cleanup.** `after_server_stop`, `after_stop` and `after_command` run while Taskiq and NATS are still open, so they can still publish and enqueue. Then Taskiq and NATS close, since their shutdown hooks may still write through the database; the model cache's pending invalidations finish; and the memory cache, the Redis clients and the database engine close. The Web service and commands used to close Taskiq and NATS before the hook, and the simple service closed the database before them. The base hooks no longer close anything, so an override need not call `super()`. The cleanup runs even when a hook fails, including a failed `before_server_stop`, after which Sanic skips `after_server_stop`. Commands of a Web service now close the database engine too.
- **Permission checks read `request.ctx.user` instead of the session.** `login_required`, `staff_required`, `superuser_required`, `HTTPMethodView.require_authenticated` / `require_staff`, and the Admin permission checks accept a user however the request authenticated. Where no pipeline runs — a bare Sanic application with only the Session extension, a hand-built test request — they fall back to the session as before.
- **Taking access away ends the user's logins.** Sessions and access tokens carry the access flags they were opened with. Disabling or deleting a user in the Admin, or saving one with a changed active, staff or superuser flag, now ends that user's sessions and revokes their access tokens; profile-only edits do not. So do `changepassword` and `createsuperuser --update`, which used to leave existing sessions alive. `oldman.auth.user_access_flags(user)` gives project user-management views the before/after comparison.
- The Table pipeline methods — `apply_filters`, `apply_search`, `apply_ordering`, `paginate` — take their rows or query positionally only, so an override may name that parameter after what it receives (`rows` in memory, `query` for SQLAlchemy). Every call in the framework and the demos already passed it by position.
- **CSRF protection follows the credential.** A request authenticated by a credential the browser does not attach on its own (`Authentication.ambient` false) is not checked; a request that also carries a signed-in session always is.
- **Model cache entries are filled only from a fresh transaction on the cache pool**, never through the caller's session, which may hold uncommitted writes or a snapshot older than the counters the entry would be stored under. A caller with uncommitted changes to the model, or in a process whose invalidation of that model has not landed yet, reads through its own session and stores nothing. Sessions that never write a cached model no longer run any cache code: the after-commit and rollback listeners that used to be registered on every `Session` are attached to a session the first time it writes a cached model. An invalidation that cannot start — no running event loop, the task manager stopped — is now logged as an error, as is one that fails or takes longer than five seconds; the commit itself is never affected.
- `safe_cancellable_sleep()` clears the task's cancellation count when it swallows a cancellation, however many times the task was cancelled. A `TaskGroup` in the task's cleanup then reports its children's errors; with a count left over it ended cancelled on Python 3.13 and later.
- User ids must be exactly `int` wherever the framework takes one. `get_user_by_id`, `change_user_password` and `touch_last_login` in `oldman.auth` accepted an `int` subclass such as an `IntEnum` member, which the session store, token issue and revocation refused; they now raise `TypeError` for it too. `oldman.security.require_user_id()` is the one check.

### Deprecated

- **`AsyncConfigDict` and `RedisSettings`** warn when constructed and keep working. `AsyncConfigDict` handed out untyped data, so each subclass decoded records itself and kept a cache that its own saves never refreshed. Replace an `AsyncConfigDict` subclass with `YamlStore[Schema]` and move `get_empty_data()` into the schema's defaults; replace `RedisSettings` values with a `RedisStore` schema and its sets with `RedisSet`. Lists and per-value TTLs have no replacement. `RedisSettingsClient` is now `BinaryRedisClient`; the old name remains as an alias.

### Fixed

- **`app_settings.admin.require_superuser` was only checked at the Admin sign-in.** Model pages looked at the model's own `require_superuser` alone, so a staff session that reached the Admin some other way — signed in to another service sharing the session — could open any model its roles allowed. Every model page now honours the site-wide setting too, as do the Admin index and the user's own session page and password change; the sign-in page no longer sends such a login on to pages that refuse it.
- **Generic Admin pages were half English.** A plain `ModelAdmin` built its list title, New button, form heading, submit button and delete label from English f-strings ("New 角色", "Create"), which the renderer passes through untranslated. They are now translatable messages with the model name filled in.
- **The framework's own denials were English.** Tables, charts, `HTTPMethodView`, `permission_denied_response`, `staff_required`, `superuser_required`, `require_perm` and the SSE guard put literal "Permission denied" or "Authentication required" into JSON errors. They now answer in the request's language; a message the caller passes is used as given — by tables too, which used to drop the one `check_permission` returned.
- **A refused table, chart, modal or select showed the transport's English.** When a request failed, these components displayed Axios's own text, such as "Request failed with status code 403", whatever the page language. They now show the `message` of the framework's own API error responses (those carrying `error_code`), which the server has already translated — the request errors of tables, charts and selects (an unknown filter or sort, a bad parameter) included, which used to be English; Sanic's generated error bodies are English diagnostics and are not shown. Otherwise a 403 reads "Permission denied" and anything else "Request failed", both through the frontend catalog. `httpErrorMessage(error, i18n)` in `oldman-web/core` is the one place that decides this; the six copies of the old rule are gone.
- **Two services on one Redis database shared fingerprint blacklists and model cache entries.** Fingerprint security keys (`blacklist:ip:…`, `rate:fp:…` and the rest) and most model cache keys (`i:`, `f:`, `q:`, `rev:`, `qs:`) carried no prefix at all, so one service's blacklist blocked visitors of the other and cached rows could be read across services. They are now under the service namespace.
- **Staff could make themselves superuser.** In the Admin user manager, and in any site built on the shared user form, a staff user who was not a superuser could tick superuser on their own account or anyone else's, and could reset the password of, disable or edit staff and superuser accounts. Now only a superuser may create, edit, delete, enable or disable, or reset the password of a staff or superuser account, or tick either flag; anyone else gets "Permission denied". The shared user form enforces this for create and edit, judging by the request it is bound to; views that delete, toggle or reset without the form check `oldman.auth.is_ordinary_user(user)`, as the Admin does.
- **`jwt_decode` now checks `nbf`, `aud` and `iss`.** A token was accepted before its not-before time, and audience and issuer were never compared. `jwt_decode` takes `audience=` and `issuer=`; a token that names an audience is refused when the caller expects none, so a service that does not say who it is cannot accept tokens meant for another. A boolean `exp` or `nbf` is rejected rather than read as 0 or 1.
- **The model cache could return the wrong row.** `CacheableModel.cached_get()` keyed its field lookups on the first two letters of each field name, so `cached_get(employee_id="5")` was answered with a cached `email="5"` row, and `user_id` / `username` collided the same way. Field keys now carry full field names in an unambiguous encoding, and the type of each value: JSON writes an enum member as its value, so `shape="r"` was also served the row cached for `shape=Shape.ROUND`, which the database does not return for the string. All model cache keys (`cached_model` and `cached_model_simply`) now name the model by its import path rather than its class name, so two same-named models in different Apps no longer share entries.
- **`AsyncConfigDict.save_data()` could get the configuration wiped.** The save deleted the file before moving the new one into place, and an instance that finds its file missing writes empty data back. Another process's instance checking in that window replaced the configuration with an empty one. The save now relies on the atomic replace alone, so the file never disappears.
- **`ManagedSubprocess.wait()` and `communicate()` without a timeout turned an inner `TimeoutError` into `UnboundLocalError`.** The handler meant for their own deadline read a variable only set when a timeout was given. The process group is still cleaned up, and the original `TimeoutError` now surfaces as it is instead of being reported as a subprocess timeout.
- **The model cache returned stale and wrongly typed rows.**
  - A row inserted after a query was cached, or changed so that it newly matched, stayed out of the cached result for up to five minutes. Each entry now records the generations of what it depends on, and a committed write advances them; the writing process sees its write at once and other processes after one Redis round trip.
  - An invalidation racing a new query could leave that query cached with nothing left to invalidate it.
  - Savepoints were taken for the end of the transaction. Releasing one invalidated at once, while the transaction was still open, so a read in between stored the old rows again under the new generations and they stayed after the commit; the writer, reading inside its own transaction, did not see its writes either. Rolling back a savepoint, or a flush failing inside one, discarded the invalidation of the whole transaction, so the writes committed around it stayed hidden behind the cache. Invalidation now waits for the outermost commit, and only a transaction that ends without committing — rolled back, or its session closed — drops what it wrote; a session closed that way used to keep bypassing the cache.
  - A write to a model whose primary key is an enum or a datetime left its cached rows in place: the write named the row `Region.NORTH` or `2026-09-01 08:00:00`, the cached entry `NORTH` or `2026-09-01T08:00:00`, so updated rows read old and deleted ones were still found. Both sides now name the key as the row is stored; integer, string, UUID and date keys are named as before.
  - Rows the database changed by itself through a cascading foreign key stayed in cached results.
  - Dates and times read back as ISO strings and a `timedelta` could not be stored; every column now reads back with the type a database read returns. Float NaN and infinities read back as None (JSON has neither) and now keep their value, `Float(asdecimal=True)` columns keep their `Decimal`s, and an enum column assigned a member's name inside the transaction no longer breaks the read that bypasses the cache. Cached rows used to come back without an identity, and their relationships read as empty.
  - Query keys were built by rendering the statement with literal values, which fails for some column types and ignored the actual dialect; they now come from SQLAlchemy's statement cache key.
  - `cached_get_many` mixed detached rows (hits) with rows attached to the caller's session (misses), and keyed a hit by the key the caller passed but a miss by the database's (`"1"` against `1`); every path now uses the caller's key. It also stores the rows it missed in one Redis round trip rather than one each: 200 rows fill in about 10 ms instead of 24.
  - An invalidation still running when the process stopped was lost, leaving entries stale until they expired: `asyncio.run` cancels unfinished tasks when a command returns, and a stopping service cancelled its background tasks. Invalidations are now held by the model cache itself, and CLI commands, the Web and simple services, Taskiq workers and process workers wait for them before closing Redis — and still close it when the wait is cancelled, by a Ctrl+C say. A script of your own calls `await wait_for_invalidations()` from `oldman.db.sqlalchemy.cache` before it exits; once it returns, reads of those models use the cache again.
- **`DatabaseModel.model_validate_json` read dates back as strings.** It decided which fields were dates by looking at the class attribute, which on a mapped model is always the attribute descriptor, so no value was ever converted. `model_dump_dict`, `model_dump_json` and `model_validate_json` now share the model cache's column codec: every column reads back with its own type (`date`, `datetime`, `time`, `Decimal`, `UUID`, enum members, `bytes`, `timedelta`). `model_dump_dict` returns JSON values throughout — before, only datetimes were converted — and leaves out relationships, which used to make the dump fail; enum members are dumped by name. A key that is not a column, or a column of a type without a verified JSON round trip (a project's own `TypeDecorator`, `ARRAY`), raises `TypeError`.
- `CollectionUtils.try_call(..., args=...)` with a generator gave the arguments to the first function only; the next ones were called without them. `args` is now read once into a tuple.
- `OptimizedFixedSizeList.append()` stored an unhashable item before failing on it, and once that item was the oldest every later append failed until `clear()`. It now refuses the item before storing anything.
- At interpreter exit, `MultiHttpClient` logged that it was cleaning up every client ever created, including ones never opened, which hold nothing to close. The line landed on stdout after a script's own output, breaking callers that read that output. It now counts and closes only clients still holding a connection pool, and logs nothing when there are none.

## 0.2.0 — 2026-09-22

The browser package and the Python package are updated together. This release includes breaking changes, so the minor version is bumped accordingly.

### Breaking Changes

- **Browser translation attribute renamed**: `data-key` → `data-om-i18n-key`. The framework no longer claims the unprefixed global selector `[data-key]` — that name belongs to the application using it. **No compatibility layer**: rename it directly in your templates; `oldman-web` no longer looks up `[data-key]`.

### Added

- **Mail**: an async outbound layer modeled on `django.core.mail`, rendering templates in the recipient's language, with a `mail sendtest` service command and an SMTP round-trip test.
- **Password reset**: tokens, lookup by email, dedicated settings, and rate limiting; `PasswordResetFlow.register_routes` sets up all six views at once.
- **Browser fingerprinting**: an opt-in subsystem with a browser half and a matching server half; nothing requires it.
- **Auth decoupled from Admin**: user forms and management rules, the shared user table, status and delete modals, login steps, and `safe_next_url` moved into `oldman.web.auth`, usable without installing Admin.
- **Table**: a toolbar (selection count, bulk action slots, column menu, density), CSV export via the data endpoint, a sticky header, an in-table empty state with filter reset, an inline filter bar, shared cell primitives, and `RowAction`.
- **Form**: a boolean control, `FieldGroup`, column-level labels, a `before_save` hook, a remote Select that owns its own initial options, and `EmailField` storing each address in only one form.
- **i18n**: the framework builds its own browser catalog and language manifest; it refuses to start if a configured language has no catalog.
- **Test gates**: browser, process-tree, and PNG gate helpers; two browser gates for notifications and resource ownership; and a duplication guard that can run as a plain test.

### Fixed

A line-by-line review of 16,929 lines of frontend production code found 23 defects, all cleared in this release. The main ones:

- A component with a mis-written marker no longer tears down its sibling components — each component mounts independently and marks only itself as `failed`.
- Unowned global selectors the framework previously claimed have been scoped back to their own contexts.
- The HTTP client now deregisters listeners it attached to long-lived scoped signals.
- Page teardown no longer blocks the next navigation (a 5-second default timeout, after which it recovers normally and reports an error).
- A Modal destroyed while closing now finishes that close instead of canceling it.
- Nested scoped preloaders no longer swallow each other's overlays.
- Response actions carrying a link now reject executable protocols (`javascript:`, `data:`), while still allowing normal off-site https targets.

Also a session lifecycle fix in the HTTP client: `reset_client` now discards the session even when closing it fails, instead of leaving a session that cannot be closed around for reuse.

ruff, pyright, 1,974 Python tests, the oldman-web and admin frontend test suites, and the boundary, packaging, and scaffold matrix checks all pass; real-Chrome acceptance testing was also done on both demo apps.

## 0.1.0 — 2026-09-14

The first release, providing both the Python package `oldman` and the browser package `oldman-web`.

### Main Capabilities

- Service-level YAML configuration, App registration, CLI, project scaffolding, IDE/shell initialization, and the Web, Simple, Worker, and Scheduler lifecycles.
- SQLAlchemy models and an Alembic migration entry point, JSON fixture import/export, file storage, caching, and a shared HTTP client.
- User authentication, Redis Session, CSRF, overridable error templates, cookie-based one-time messages, and persistent notifications.
- Server-side HTML forms, async validation, ModelForm, file uploads, and unified ordered JSON response actions.
- Admin/Dashboard built on shared components and a DOM protocol; HTML/JSON Table, Modal, select and input enhancements, charts, icons, and a Chinese/English interface.
- Browser SSE delivery; events and RPC via Core NATS/FastStream; persistent tasks, results, scheduling, and Worker management via Taskiq. Each of these three uses has its own explicit interface.

For usage details, see the [User Documentation](docs/public/zh/users/README.md), the [Developer Reference](docs/public/zh/developers/README.md), and the [Agent Guide](docs/public/zh/agents/README.md). Runnable examples come from the separate Admin Demo and EPG Dashboard Demo; see the [Demo Index](docs/public/zh/users/demo-examples.md) for entry points.

### Fixed During This Round of Acceptance Testing

- Before finishing NATS subscription startup, confirm the server has received the subscription, avoiding occasional "no responders" when another connection issues an RPC immediately after; the normal publish path gains no extra round trip.
- When a TLS reconnect rejects a plaintext endpoint, it now closes that connection, avoiding an old socket that can only wait for garbage collection after being overwritten. Sending credentials in plaintext is still rejected.
- Dropdown and Popover now handle only their own Escape key, no longer stealing the close key from a Modal opened from a menu.
- Fixed the type annotations of the multi-select tag Widget and the type paths of public frontend components. Outdated gates were corrected to match the actual runtime protocol, not restored to the old interface.

### Scope and Deployment Notes

- Linux; Python 3.12/3.13; Node.js 20 and above; applications use Tailwind CSS 4. Framework development is pinned to pnpm 9.12.3.
- Python and npm versions must match. Application deployment needs its own dependency lock, real connection configuration, migrations, and static asset collection; a source checkout link cannot substitute for deploying the release package.
- Distributed tasks do not guarantee strict exactly-once execution; for specific scenarios such as lost acknowledgments or a Worker exiting mid-task, and how to handle them, see the [Task Documentation](docs/public/zh/users/distributed-tasks.md).
- Chrome was the browser actually used for acceptance testing this round; this does not mean other browsers are disallowed. Database, browser, and production-capacity verification that was not performed cannot be substituted by unit test results.
- The MIT license and the bundled third-party license files are retained; specific deployments must still review the licenses of the application's own dependencies and resources.

Before deploying, see the [Deployment Guide](docs/public/zh/users/deployment.md).
